# AIメシモリ Muse版チュートリアル（他の Muse エージェント向け）

これは **Muse 版（アーティファクト版）** の導入チュートリアルです。
prd 版（ローカル版）のチュートリアルは `prd/docs/local-setup-for-agents.md` で、方式が違います。こちらはサーバを立てません。あなたの Muse 環境の中にアーティファクトとして用意し、食事・体重の記録はアクション経由で読み書きします。データはあなたの環境の外に出ません。

進め方は **単純な Q&A 方式** です。人間への質問は簡単なものだけ、技術的な報告は人間に見せません。

## 0. 前提

- Muse の環境であること（アーティファクトが使えること）。
- データモデルとアクションの仕様は `muse-prd/docs/aiseki-artifact-design.md` が正。
- 個人設定（1日の標準 kcal など）は、その人のそばにいる AI（あなた）が、その人について知っていることから決めるのがこのアプリの流儀。他人の設定値を持ち込まない。

## 1. 準備（エージェントの作業。人間には見せない）

1. 設計書（`muse-prd/docs/aiseki-artifact-design.md`）どおりに、AIメシモリのアーティファクトを用意する。
2. `get_settings` を呼んで接続を確認する（応答が返ればよい）。
3. この時点ではまだ人間に何も報告しない。先に §2 のヒアリングを済ませてから案内する。

## 2. 初期設定の聞き方（人間向けヒアリング）

セットアップの前に、簡単な質問で初期設定（1日の標準 kcal）を決めます。prd 版のヒアリングと共通の方式です。質問攻めにせず、ざっくりでよいと伝えること。

1. 「身長と今の体重を教えてください（ざっくりでOKです）」
2. 「年齢も、年代だけでも大丈夫です」
3. 「目標はどれですか？ ①維持 ②少し減らす ③しっかり減らす ④増やす」
4. 「普段の活動量は？ ①よく動く ②ふつう ③あまり動かない」
5. 「医師から食事量の指示はありますか？（あれば、それを最優先します）」

算出: 標準的な推定式（基礎代謝 × 活動量）で維持量を出し、目標に合わせて調整する。極端な制限はしない（維持量の8割未満にはしない）。医師の指示がある場合はそれを最優先する。
結果は一文だけ伝える: 「あなたの標準は1日 ○○kcal にしました。ゆるく行きましょう 🍚」のように。
決めた値は `update_settings` で投入する（target_kcal / current_tz / week_start）。

## 3. 人間への案内（台本）

準備と初期設定が終わったら、利用者へ案内して運用を始めること。

**人間向けの説明は最小限に、楽しく（最重要）**: セットアップの技術的な報告（アーティファクト・アクション・DB・ドキュメント名など）は人間に見せない。人間に伝えるのは「やること」だけ。文面は絵文字を使って楽しく、口調はフレンドリーに。

1. 完了は一文で: 「準備ができました 🎉」
2. やることだけを伝える:
   - 「あなたがやることは2つだけです」
   - 「📸 食事の写真を送ってください」
   - 「⚖️ 体重を送ってください」
   - 「あとはAIがいい感じに記録します」
3. 見る方法を伝える: 「📅 記録はこの画面（アーティファクト）からいつでも見られます。チャットで『見せて』と言ってくれても大丈夫です ✨」
4. 最初の1件を一緒に記録する（§4）。

## 4. 最初の1件を一緒に記録する

1. 利用者が食事の写真や情報を送ってきたら、足りない情報だけを簡単な質問（いくつか）で確認する。長々と聞かない。
2. `next_meal_external_id` で採番し、`upsert_meal` で記録する（データの規約は設計書どおり）。
3. `get_day` でその日の合計を確認し、結果を表形式で楽しく見せる（人間向けのまとめは表形式がおすすめ）。

## 5. 既存のローカル版（prd 版）からの移行

すでにローカル版で記録がある家庭は、次の順で Muse 版へ移します（アップグレード）。

1. ローカル版の全レコードを取得する（GraphQL の calendar / day やエクスポート手段で、食事と日次を external_id が分かる形で）。
2. `import_records` でアーティファクトへ一括投入する。
3. 日別の actual 合計と体重を、移行元と突き合わせて一致を確認する。一致しない場合は切り替えない。
4. 切り替え日を決め、その日以降の書き込みはすべてアーティファクトのアクションへ向ける。二重書き込みの期間を作らない。
5. 移行元のローカル版は、しばらく読み取り専用として残す（削除は利用者側の判断があるまでしない）。

## 6. prd 版チュートリアルとの違い

| 項目 | prd 版（ローカル版） | Muse 版（この文書） |
|---|---|---|
| 用意するもの | リポジトリを clone してサーバを起動 | Muse 環境にアーティファクトを用意 |
| 記録の書き込み | ローカル API（GraphQL）へ直接 | アクション経由のみ |
| 画面の見せ方 | テンプレート＋データ流し込みで生成して提示 | アーティファクトを自分で開くのが主。チャット提示も可 |
| 常駐 | サーバの常駐が必要 | 常駐なし |

初期設定の聞き方（§2）と、人間がやることが2つだけという前提は、両版で共通です。
